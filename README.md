# WebSockets



## Завдання 1: Чому HTTP недостатньо? Дослідження обмежень

### Відповіді на питання для роздумів:

* **Скільки HTTP-запитів робить WebSocket для встановлення з'єднання?**
  WebSocket робить **рівно 1 (один)** HTTP-запит, який називається (Handshake). Клієнт надсилає стандартний `GET`-запит із обов'язковими заголовками `Upgrade: websocket` та `Connection: Upgrade`. Якщо сервер підтримує цей протокол, він повертає відповідь із кодом `101 Switching Protocols`, після чого з'єднання трансформується у двосторонній WebSocket-канал, а HTTP-протокол більше не використовується.

* **Якщо в чаті 1000 користувачів і всі «поллять» кожну секунду — скільки запитів за хвилину отримує сервер? А при WebSocket?**
  * **При HTTP Polling:** Сервер отримуватиме 60000 HTTP-запитів за хвилину. Більшість із цих запитів будуть «пустими» (сервер повертатиме відповідь, що нових повідомлень немає), але сервер все одно витрачатиме колосальні ресурси процесора та мережі на обробку заголовків та перестворення TCP-сесій.
  * **При WebSocket:** Кількість HTTP-запитів після ініціалізації дорівнюватиме **0**. Сервер триматиме всього 1000 відкритих TCP-з'єднань. Трафік почне ходити лише тоді, коли реально з'явиться нове повідомлення. Це знижує навантаження на сервер у тисячі разів.

* **Назвіть 3 реальних застосування WebSocket:**
  1. **Месенджери та чати** (Telegram Web, Discord, чати підтримки) 
  2. **Багатокористувацькі онлайн-ігри (ММО)** (наприклад, Dota 2, CSGO,CSGO2,CSGO228 чи шутери)
  3. **Платформи для спільної роботи** (Google Docs, Figma, інтерактивні дошки завдань).
